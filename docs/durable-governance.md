# 持久化运行治理

本模块把单次进程内的治理，扩展为**同一主机上多个 Keel 进程共享额度和审计记录**。
默认关闭；启用后接入真实 Runtime、模型调用、工具网关、源码写入和验收路径。
它不是 Ray/Kubernetes 控制平台，也没有提供可被不可信客户端直接访问的 HTTP 接口。

## 配置和运行

在已有合法任务配置中增加：

```json
{
  "governance": {
    "path": "D:/KeelControl/control.sqlite",
    "scope": "tenant-a/campaign-20261115",
    "max_tokens": 120000,
    "max_model_calls": 20,
    "lease_seconds": 900,
    "denied_tools": ["mcp__search__web_search"]
  }
}
```

该路径必须在待修复仓库之外，权限由可信操作者管理。多个任务使用相同的 `path` 和
`scope` 时，共享该 scope 的累计额度。额度不随新进程、运行结束或重新打开数据库重置。
相同 scope 的额度、禁用工具策略必须一致；调整政策要显式建立新的 scope，不能让工作
进程增加旧 scope 的权限或预算。不要把 scope 当成身份认证机制；当前调用者是可信宿主。

`lease_seconds` 必须大于本次 Runtime 的墙钟预算，避免没有后台心跳时误判阻塞调用。
这是第一版的有意边界：失联发现较慢，不是生产级秒级故障探测。

真实模型请求先提交 `model_intent` 和额度预留，再调用提供方。返回已知 usage 后结算；
失败且 usage 未知时保留额度。内置 `FrozenModel` 在其重试循环内部接入治理，每次提供方
尝试分别预留；第三方带隐藏重试的客户端不自动获得逐请求计数保证，需要实现
`bind_governance` 或禁用内部重试。

当前预留采用消息、Schema 的 UTF-8 字节估算加输出额度，**不是提供方精确计费承诺**。
提供方返回量超过预留会记录实际消耗并拒绝把该调用视为正常完成；这种检测不能撤销已
发生的开销。精确硬额度还需提供方配额、可信 tokenizer 和一致的请求封装。
原有任务内 Budget 与上下文容量检查继续生效，共享额度不替代它们。

## 权限与审计

- 工具仍先经过角色目录、参数及路径检查，再检查运行级 `denied_tools`。
- 已知的宿主直接搜索与写入路径也检查禁用策略；不是只在模型工具描述里删名字。
- 写入前保存路径、修改前后哈希及动作编号，验收前后保存命令、退出状态与本地证据引用。
- 记录意图是执行前置条件。关键记录不可写时阻止新操作；最终治理记录失败会把本地
  `result.json` 标为失败，不能沿用之前的通过结果。
- 事件不保存完整提示词、凭据或源码正文；正文仍在任务账本/产物中。

`denied_tools` 是精确工具名策略，不是自然语言语义识别。禁止一个搜索工具不能证明其他
只读工具无法获取同样的信息；评测禁网需要网络策略，任意 shell/外部 MCP 也不由本模块
自动隔离。SQLite 文件在宿主可修改，当前没有远端防篡改存储或租户鉴权。
把控制库放在仓库外只能限制受控文件工具；若用 local 后端运行不可信代码，它仍可能
访问宿主文件。生产隔离还需要独立身份、受限挂载和受保护的远端控制服务。

## 失联、核查和操作检查

每次关键事件续租。检查器可把过期的 `running` 记录标为 `unreachable`，将其未结算模型
请求标记为 `unknown`，不释放占用、不重放补丁、不推断远端调用没发生。
租约到期的旧会话不能继续提交动作；迟到 usage 可幂等结算，但不恢复执行权限。
管理员根据原始操作记录核查之后，才能决定下一次工作；没有自动崩溃续跑接口。

```powershell
python -m examples.inspect_governance --db D:/KeelControl/control.sqlite --scope tenant-a/campaign-20261115
python -m examples.inspect_governance --db D:/KeelControl/control.sqlite --scope tenant-a/campaign-20261115 --run-id RUN_ID --limit 100
python -m examples.inspect_governance --db D:/KeelControl/control.sqlite --scope tenant-a/campaign-20261115 --reconcile-expired
```

事件使用全局递增序号分页，返回 `next_after`，调用者保存游标可重新读取；这不是可靠消息
投递/消费确认系统。数据库必须预先存在，检查命令不会创建空库冒充有效结果。

运行不使用模型、网络或 Docker 的真实本地演示：

```powershell
python -m examples.demo_governance --output .keel/governance-demo-v1
```

演示真实修改一个版本常量并运行本地断言，保存 Runtime 产物及治理事件。输出目录已存在
时保留旧结果并报错，不自动重复执行。测试：

```powershell
python -m unittest tests.test_governance -v
```

检查包括六个真实 OS 进程竞争额度、进程在提交请求记录后直接退出、重启核查、未知用量
保留、重复结算、禁用搜索和写入、必需审计失败阻断，以及真实 Runtime 的无模型验收与
脚本模型 Agent 流程。脚本模型仅检验接口，不是提供方实测或修复质量基准。

## 存储与生产化边界

当前每个写事务有两秒数据库等待上限，使用 SQLite 事务串行化共享额度更新。它适合
受控同机协调，并不承诺高并发吞吐；不要把这个数据库挂在多节点共享网络盘上共同写。
进程崩溃后已提交记录仍在，但宿主磁盘丢失不会凭空恢复。Kubernetes 使用时需要适当
的持久卷、一致性备份及恢复检查，本仓库尚未实测这些部署条件。

后续生产接入仍需逐项验收，不能用本地测试代替：

| 工作 | 第一版状态 | 接入要求 |
| --- | --- | --- |
| 同机原子共享额度、调用意图和结果记录 | 已实现 | 本地事务、进程并发与故障检查 |
| Ray 调度 | 未接入 | 每次尝试预留、幂等任务、重启后外部状态核查 |
| Sidecar/节点监控 | 未接入 | 受控出口、可信身份、独立心跳与防绕过验证 |
| 跨沙箱证据服务 | 未接入 | 租户授权、内容哈希、版本绑定、幂等交接 |
| MySQL 权威状态、Redis 协调 | 未接入 | 事务/CAS、故障转移与一致性检查 |
| S3 大产物与 ES 检索 | 未接入 | 先确认产物再提交完成状态、outbox、派生索引 |
| 生产负载/SLA | 未验证 | 峰值吞吐、尾延迟、积压、预算误差及故障注入 |

不默认安装服务、调整网络、修改操作系统或调用付费模型。
